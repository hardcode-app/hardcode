# This profile's allowlist: its own entries, and the entries HardCode
# provides that it switches off. Squid (HTTP/HTTPS, inspected) and CoreDNS
# (DNS) let traffic out only to what the allowlist allows.
#
# The provided entries aren't in this file. They come in blocks: those every
# profile has (VS Code, OS package mirrors, container registries, GitHub raw
# files) and those of the languages and tools the profile has on. They
# follow HardCode's updates: an entry a newer HardCode adds arrives switched
# on, and one it drops goes. `hardcode allowlist` lists everything, provided
# and your own, as the app's and the admin's Allowlist do.
#
# An entry:
#   example.com             that host, any URL
#   .example.com            that host and every subdomain
#   example.com/some/path   only URLs under that path
#   <entry> rw              uploads allowed too
#   example.com[:port] ssh  an SSH tunnel (port 22 by default). SSH can't be
#                           inspected, so this is whole-host and read-write.
#
# Entries are read-only unless marked "rw": GET, HEAD, OPTIONS and the POST
# git uses to clone/fetch/pull. So a registry or package index can be pulled
# from but not pushed to, and a git namespace can be cloned but not pushed to.
# "rw" is needed for APIs that take POST, login flows, and anywhere you push
# or publish. "rw" counts as an upload target: with credentials, data can be
# sent there. Keep those entries short.
#
# One entry per line, "#" starts a comment; an entry of yours commented out
# is switched off. "off <entry>" (or "off <host[:port]> ssh") switches off one
# of the provided entries: it stays off through updates and language
# switches.
#
# On your network: the proxy refuses any name that points inside your own
# network, so an allowed name can't reach your computer, your local network
# or a cloud metadata service. To let one of your own servers through:
#   lan gitlab.example.com 192.168.71.200
# That name may then reach that address, and nothing else opens. The name
# still needs its own entry above, and DNS can't move it elsewhere. One
# exact name and one address on your network per line, never one of this
# computer's own addresses (a line written for one is left out), one in the
# sandbox's own network (DEVNET_SUBNET) or one in Docker Desktop's
# (192.168.65.0/24): HardCode refuses those, and the proxy refuses every
# address of the networks it is attached to, whatever a line says.
# `hardcode allow` asks before adding one, and `hardcode lan` lists them.
#
# Apply changes:  `hardcode allow` / `hardcode deny`, `hardcode allowlist
#                 enable|disable` or the HardCode app do it for you; after
#                 editing this file by hand: hardcode reload
